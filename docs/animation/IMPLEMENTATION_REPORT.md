# G1–G5 三维动画基础：首轮实施报告

首轮日期：2026-09-27；最近优化：2026-10-18。性质：本地 Windows x64 开发预览，不是新的公开 Release。

## 结论

G1–G5 的首轮工程链路已经打通：统一三维骨架、外部动作导入、独立实验场、连续运动、双人接触原型，以及图标/桌面实验入口都可运行。

这次证明的是“可以用同一套骨架和播放器持续扩展”，不是“已经无限接近真人”。普通行走等动作使用真实动捕；庆祝、握手和拥抱仍是自编排的验证素材/约束原型，观感还需要继续打磨。自动测试通过不等于原计划的全部人工验收通过。

原计划先在 G1 等待人工观感确认；用户随后明确授权离开期间自主推进至 G5。本轮据此完成可逆的工程原型，没有擅自把人工观感结论标成通过，也没有替换旧产品、发布新版本或购买设备/素材。

## 2026-10-18 第五轮：双人下肢统一与稳定性

用户进一步发现双人示例脚掌倾斜、两人的腿脚持续抖动。实测旧逻辑在站定接触阶段脚掌最大倾斜约 24.9 度，单帧脚掌转动约 1.57 度，膝盖最大单帧移动约 40.7 毫米；脚底接触点本身却几乎不动。第四轮中立骨盆/上身与仍保留的捕获下肢旋转并不一致，点接触求解没有约束完整脚掌姿态，变化的膝盖参考又带来求解跳动。之前仅测不穿地、固定骨长和手部接触不足以发现这些问题。

- 双人底姿不再继承 idle 的下肢旋转与骨盆高度轨道，仅保留上肢放松；以现有骨架重建对称站姿，比例和单人动作数据不变。
- 新增独立双人下肢求解，统一脚掌位置与朝向。保持阶段脚掌水平、轻微对称外展；当前迈步也保持水平抬脚，不假装是已精修的脚跟/脚尖滚动。
- 采用平滑步进、按步长调整抬脚高度，保留膝盖弯曲余量，并以角色前向定义稳定弯曲平面。骨盆与可达范围共同求解，不拉长骨骼，不依赖上一帧的源膝盖方向。
- 近距离拥抱时脚尖保留净空；取消时锁住已落地脚的水平位置，空中脚原位落下。普通单人脚底修正和原始动捕完全不改。

15/15 CTest 通过，三维断言 2,305,458 次通过。54 组身高比例/距离组合覆盖完整接近、保持与退回：脚掌法线最大偏差约 0.00000342 度，保持阶段采样脚底漂移、踝关节漂移与膝盖逐帧位移为零（浮点采样结果，不是物理精度承诺）。完整迈步最大膝盖单帧位移约 23.1 毫米，60 Hz 差分加速度峰值约 30.3 m/s²；这两项用于排查短步中的突变，不作为人体标准。

同时检查了所有脚掌组合在接近方向上的净空、脚掌朝向、膝盖前弯、原有头颈与掌面约束。48 组取消情形覆盖两类互动、对称/不同身高、近远距离与四个时点，验证不跳姿态、不穿地、支撑脚水平位置不漂移；时间轴拖动与连续播放的下肢结果一致。原有掌面目标残差约 0.000516 毫米，采样手臂到对方躯干最小净空约 2.79 毫米；没有放宽原接触阈值。

新增十张双人下肢近景 `pair-feet-handshake/hug-0..4.png`，并重建双人全身图和视频；已目视检查中立、迈步与保持姿态。仍是几何约束与简化步态原型，不等于完整真人步态或所有肢体碰撞的验收。旧实现与预览备份在 `out/animation-foundation/pair-feet-calibration/before/`。当前实验程序为 958,464 字节，实验 Besktop 为 2,011,648 字节；动画资源与 Blender 工程未改变。源码和文档在开发分支保存，本地预览、素材缓存和构建产物不入 Git；尚未创建本阶段的公开 Release。下文各轮保留当时的实施状态。

## 2026-10-18 第四轮：双人底姿与头颈（历史实现）

用户指出复位后脖子正常，而握手/拥抱示例歪头。定位为两条路径底姿不同：复位仅回到当前单人片段的起点（默认 walk），双人示例则曾逐帧复制同一个 idle 姿态。原 idle 首帧颈到头部的方向约偏离竖直 14 度，原样继承后成为所有双人互动的默认姿态，并非专门设计的头部表演。

- 在双人路径中清理骨盆/脊柱/胸部倾斜和头颈姿态，保留捕获的肢体放松及高度变化；双方使用错开的 idle 相位。骨架偏移、骨长、比例 v4 与所有单人片段不变。
- 两段颈部通过旋转对齐中立方向，不改关节位置来拉直脖子。握手依据双方基准头高差加入受限俯仰，拥抱仅在接触包络内侧头约 8 度；开始、释放和取消恢复至中立姿态。它是受限的示例编排，不是完整眼球注视或解剖颈椎模型。
- 视线意图使用落定参考姿态的头高差，不直接追逐脚底 IK 对骨盆高度的逐帧修正。新增检查曾捕获释放阶段的头颈跳变，按此隔离后通过；没有调宽失败阈值。
- 新增六张 `pair-neck-handshake/hug-0..2.png`，同一上半身机位记录起始、接触和恢复；双人多角度图及 32 秒视频随运行时重新生成。Blender/普通动作数据未改变，双人接触本来就在运行端求解。

15/15 CTest 通过；三维断言 1,680,726 次通过。54 组比例/距离组合检查中，上段颈部最大倾角约 10.55 度（同时含身高差俯仰和拥抱侧倾）；握手侧偏、开场/收尾中立、两段分担弯曲、逐帧连续、取消不跳姿态、拖动时间轴与连续播放一致、原始单人片段不变均已覆盖。倾角包络是当前原型约束，不是医学限值。

双人掌面目标最大残差约 0.000391 毫米，可见脚底下探低于 0.001 毫米，采样手臂到对方躯干最小净空约 2.78 毫米。原有接触和固定骨长检查未放宽。隐藏原生 UI 和 48 图标合成舞台测试通过，UI 路由新增了双人开场头颈检查。画面复核确认开场不再继承原素材歪头；自然度仍由用户继续评估。

当前 `AnimationLab.exe` 为 949,248 字节，实验 `Besktop.exe` 为 2,002,432 字节；内嵌动作资源未变。100 演员的最终 1080p 完成帧均值为火柴人 2.065 毫秒、图标 2.812 毫秒，仍仅作本机短测记录。之前的实验程序和接触截图备份在 `out/animation-foundation/pair-neck-calibration/before/`。未提交、推送或发布。

## 2026-10-18 第三轮：比例溯源与回归（v4 比例）

按照用户确认的方向，加入固定版本的人体运动参考、端点快照、推导脚本和配置漂移检查。公开来源核实后，选择 OpenSim Rajagopal2016 模型的中立位腿部框架跨度作为有限参考，没有把 CT 股骨/胫骨长度或未核验的国标网页转录直接当作动画骨长。完整来源、口径与复算步骤见 [人体比例依据](ANTHROPOMETRY.md)。

原模型框架跨度比为 1.029199723；保留角色原有总跨度 0.87 米，得到大腿 0.441259551 米、小腿 0.428740449 米。相对 v3，各段仅调整约 1.26 毫米，已认可的肩颈、手臂与躯干形体不变。此次主要成果是可追溯、可复算、可回归，不是大幅拉长大腿；其他身体参数仍属工程选择，尚未完成国标人群体型或个体拟合。

9 项离线比例单元测试通过；另用原 XML 的固定 SHA-256 和实际节点独立复核了左右腿快照。每次导入前校验来源单位、配置版本、非有限值及目标长度一致性；导出 `anthropometry-audit.json` 并随本地预览包提供，骨架元数据记录来源提交。C++ 另有四项实际导出跨度/比值断言，避免 exporter 和自生成 golden 同时漂移。六条动作、Blender 工程、EXE、四视图和视频均重新生成。

15/15 CTest 通过，三维断言 1,555,214 次通过。导出参考与运行时 FK 最大差约 0.507 毫米；Blender 实际骨骼核验误差约 0.000000246 米。1,205 个单人采样姿态的脚底最深下探约 0.169 毫米；支撑窗口的脚底漂移低于 0.001 毫米。54 组双人比例/距离组合继续通过，掌面目标残差低于 0.001 毫米，采样手臂到对方躯干最小净空约 2.54 毫米。未放宽这些检查的阈值。

隐藏原生 UI、48 图标合成舞台与离线渲染检查通过，不读取真实桌面。当前 EXE 仍约 941,056 字节（AnimationLab）、1,994,240 字节（Besktop）；内嵌动作资源 258,984 字节。当前比例版本为 `besktop.reference-proportions.v4`，拓扑仍为 v1。v3 配置、骨架和实验程序备份在 `out/animation-foundation/anthropometry/before-v4/`。尚未提交、推送或替换公开 Release；人工自然度验收仍保留。

本轮最终 1080p 合成基准中，100 演员平均完成帧耗时为火柴人 3.022 毫秒、图标 3.205 毫秒，图标工作集约 185.04 MiB。同轮较早一次测得图标约 4.696 毫秒，说明短测存在明显波动；不以一次结果宣称性能提升或证明没有回退。包内 CSV 记录最终采样，测量环境与方法见下文。

## 2026-10-18 第二轮：全身比例、形体和接触（v3 历史记录）

保留已认可的肩颈布局，将其余身体从源演员参考布局校准为对称角色：左右上臂/前臂分别为 31/26 厘米，大腿/小腿分别为 44/43 厘米；骨盆高度 1.03 米，左右髋关节对称。腿长对根位移的归一改为左右平均值。

- 增加简化胸腔、腹部和骨盆形体，普通外观隐藏原先像“额外腿段”的骨盆辅助连线；骨架模式仍可观察完整层级。
- 增加随手腕旋转的简化手掌和随脚踝旋转的脚掌；Blender 与运行端共用外观参数。手部采用无手指的简化整手形体，尚无抓握细节。
- 最终裁剪与循环封接后按可见脚掌重新对齐地面；运行时锁定实际脚底支撑点，保留捕获的脚踝旋转。先补偿骨盆高度，再求解腿部，并纠正摆动脚被压入地面的情况。
- 重新处理握手的掌面接触和朝向，拥抱目标从对方可见胸腔表面计算；调整绕背肘部引导，检查加宽后的躯干净空。

本轮实际发现并修复了两类回归：短腿比例下旧锁脚目标不可达，导致脚底仍漂移；躯干变宽后原绕背路径与手腕落点使前臂穿入。现在同时按腿的可达范围补偿骨盆、按可见掌面与躯干形状求解双人接触，没有放宽原有失败阈值掩盖问题。

当前验证：15/15 CTest 通过，三维断言 1,555,210 次通过。站立、行走、停止、转弯、庆祝共 1,205 个采样姿态的可见脚底最深下探约 0.141 毫米；选定支撑窗口的脚底漂移及高度求解残差低于 0.001 毫米，保留捕获脚踝旋转。站立/行走的膝盖反折检查、手脚不可达 IK 的固定骨长及过伸边界检查通过。这些是几何验证，不是人体级精度或完整解剖关节限制的证明。

54 组双人比例/距离组合通过：掌面目标最大残差约 0.000398 毫米；接近及保持阶段脚底下探低于 0.001 毫米；保持阶段采样手臂胶囊到对方可见胸腔/腹部/骨盆的最小净空约 2.54 毫米。净空改为针对实际椭球形体的检查，与此前中央躯干胶囊的数值不能直接比较；仍不覆盖所有肢体互碰或衣物。

导入参考与运行时采样最大位置差约 0.454 毫米，Blender 骨骼校验约 0.000000240 米。新增全身四视图和两张脚底近景；原生 UI、48 图标合成舞台、32 秒视频及 1080p 基准已重新生成。100 演员平均完成帧耗时为火柴人 2.009 毫秒、图标 2.692 毫秒；图标工作集约 185.19 MiB，测量条件仍见下文。

当前 `AnimationLab.exe` 为 941,056 字节，实验 `Besktop.exe` 为 1,994,240 字节，内嵌动画资源为 258,797 字节。比例配置为 `besktop.neutral-proportions.v3`；骨架拓扑仍为 v1。v2 的工程和画面备份在 `out/animation-foundation/fullbody-calibration/before/`。后续各节保留历史测量，当前构建以本节及包内新日志为准。

## 2026-10-18 第一轮：肩颈比例校准（v2 历史记录）

## 实际采用的方案

- 制作端：Blender 4.5.3 LTS 便携版，仅放项目缓存。
- 数据：CMU Motion Capture Database，经 cgspeed MotionBuilder 2010 BVH 转换；最终选择 `08_01`、`113_21`、`16_33`、`16_19`。
- 转换：BVH 世界参考旋转重定向 → glTF 2.0 → ozz-animation 0.16.0 `gltf2ozz` → 内嵌运行资源。
- 运行：C++20、Win32、D3D11、ozz 采样；Core 自己管理混合、根运动、双骨 IK 与双人时序。
- 渲染：真正的三维球体/胶囊式肢体与深度遮挡；图标贴在头部挂点，保持肩胯与动作不变，纹理面向摄像机保证可辨认性。
- 无 Unity/Unreal/Electron、联网收款、许可证服务、动捕硬件或付费素材。工具和来源的版本、地址、哈希均记录在源码配置中。

本轮遇到并处理的具体问题：

1. 不同演员的固定握手高度不可达：改为根据双方实际肩部计算接触高度。
2. 用站立姿态直接平移接近会滑行：补充专项交替落脚和收尾；这仍是编排，未伪称双人动捕。
3. 单看“停止/转弯”的片段名称选中了舞蹈/篮球表演：检查主体分类与样片后替换成普通步行素材。
4. 双人动作结束后画面返回单人、时间条不能重看：保留结束姿态，拖动和逐帧可重启该互动预览。
5. 100 个独立图标复用大实例缓冲区导致显存/驱动内存重命名放大：单图标使用小实例缓冲，替换字幕纹理时释放旧资源。相同批量验证中工作集从约 472 MiB 降至约 181 MiB。
6. 桌面挂点不使用猜测的身高：按当前采样头部位置反算场景原点，合成图标中心投影误差要求小于 0.01 像素。

### 性能与体积

以下为新引擎在 1920×1080 合成场景中，预热 30 帧后测量 120 帧的均值。每帧包含动作更新、提交和等待 GPU 完成；不是只测 CPU 提交，也不是实际桌面显示 FPS。没有做跨机器或长时间热稳态测试。

| --- | ---: | ---: |
| 1 | 0.622 | 0.369 |
| 24 | 0.822 | 0.800 |

图标模式 100 角色时，测试进程工作集约 181.34 MiB、私有内存约 160.60 MiB。该进程已生成完整视频帧及截图，包含驱动缓存，不等于普通交互窗口或真实桌面的净内存成本。1 角色两种外观的差异也受预热和 GPU 状态影响，不代表图标总是更快。

本次隐藏窗口初始化实测约 111 毫秒，合成舞台初始化约 118 毫秒；只测 `App::Create` 到可渲染，不包含用户点击、磁盘冷缓存和系统安全扫描，因此不是冷启动承诺。

- 独立 `AnimationLab.exe`：920,064 字节，约 0.88 MiB。

- 二进制均为 x64；本轮没有构建/验证新实验的 x86 版本，已发布 x86 不受影响。

完整数据与测试记录随包放在 `preview/`，每次重新运行基准可能有正常波动。

## 下一步应依据什么决定

现在不用先买动捕设备，也不用再推倒框架。优先用实验场判断三件事：单人真实动捕是否已经明显改善僵硬感、双人接触是否有可信的互动意图、图标外观是否遮挡动作表达。

如果单人动作满意而拥抱仍假，下一项应是高质量双人配对素材/采集与接触修整，而不是继续堆支付或桌面功能。如果标准火柴人本身不满意，继续修素材、比例和重定向，不把问题藏到图标后面。

本轮停在可运行、可复现、可测量的工程原型交付点；用户回来后的观感判断、真实桌面试用及是否将新舞台替换旧产品，保留为下一次明确决策。
