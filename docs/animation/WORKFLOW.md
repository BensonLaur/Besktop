# 三维骨架与资源流程 v1

日期：2026-09-27。当前是 Windows x64 开发预览，不改变 v0.1.0 的默认入口和发布物。

## 先看什么

本机交付目录：`dist/animation-foundation-preview/`。

1. `G1-G5-preview.mp4`：约半分钟的程序生成演示，依次展示行走、停止/转弯、庆祝、握手、拥抱、图标外观，不是桌面录屏。
2. `AnimationLab.exe`：独立窗口，不读取真实桌面，不需要安装 Blender、ozz、Python 或另放动作文件。
3. `Open-3D-Stage.cmd`：主动进入三维桌面实验。启动时读取壁纸、图标外观和位置，重建自己的舞台；不修改真实桌面。按 Esc 退出，备用 Ctrl+Shift+B。
4. `G1-stick-figure.blend`：制作端工程，需要 Blender；包含真实 Armature、绑定几何体、四个摄像机、全部六个 Action。默认播放 walk；在 Dope Sheet → Action Editor 中选择其他动作，并按动作长度调整播放区间。

实验包中的 `Besktop.exe` 不带参数时仍走旧 Icon Fight。不要把这个开发预览当作 v0.1.0 的替换发布，也不要覆盖原 Release 附件。

## 实验场操作

| 操作 | 行为 |
| --- | --- |
| 下拉框 | 选择 manifest 中的任意普通单人动作 |
| 空格 / P | 暂停、恢复 |
| 左右方向键 / 前后帧按钮 | 每次移动 1/60 秒，并暂停 |
| 底部滑块 | 拖动时间；双人动作结束或取消后也能重新拖动预览 |
| 0.25× / 1× | 慢放与原速 |
| 拖动画面 / 滚轮 | 环绕观察 / 缩放 |
| 1 / 2 / 3 / 4 | 正面 / 侧面 / 背面 / 斜视 |
| B / F / I | 骨架显示 / 单人脚底修正 / 图标外观 |
| H / U / C | 握手 / 拥抱 / 取消双人动作 |
| 复位 | 返回单人、清空路径、复位时间及摄像机 |
| Esc / Ctrl+Shift+B | 退出 / 备用全局退出（被别的软件占用时注册可能失败，Esc 仍可用） |

橙色线是根运动轨迹，绿色点是脚底接触目标。窗口状态栏显示动作来源、播放时间及含 Present 的本帧耗时；它不是稳定平均 FPS。双人接触有自己的求解，F 只切换单人/漫游脚底修正。

三维桌面入口仅提供 P、B、F、I 和退出键；实验场里的 H/U 不会在桌面模式误触发。当前桌面模式只接回漫游和外观，尚未接入旧格斗导演、小螃蟹、双人自动相遇与打赏 UI。

双人示例使用清理过的中立躯干/头颈底姿和独立下肢站姿，不原样继承单人 idle 的歪头、腿脚旋转与骨盆高度轨道；仅保留上肢放松，双方相位错开。握手按基准头高差设置有限俯仰，拥抱仅在接触阶段侧头约 8 度，释放和取消回正。两段颈部均通过旋转控制，不改变骨长。视线意图不直接跟随脚底修正引起的逐帧骨盆高度波动；这不是完整注视或颈椎系统。

双人下肢由 `InteractionStance` / `InteractionFeet` 统一规划和求解，单人 `GroundFeet` 路径不变。站定时同时约束脚掌位置及朝向，脚底法线竖直，左右有约 3.4 度对称外展；当前摆动脚也保持水平抬起，尚无精修脚跟/脚尖滚动。迈步使用端点速度、加速度为零的进度曲线，小步相应减少抬脚高度。骨盆保留舒适屈膝余量，膝盖参考来自身体朝向，不追逐采样素材的膝盖位置；近距离拥抱时脚尖保留间隙。取消时支撑脚不滑动，空中脚在原水平位置平滑落下。

`preview/pair-neck-handshake-0..2.png` 和 `pair-neck-hug-0..2.png` 分别检查起始、接触与恢复，避免只看接触中间帧。单人 walk/idle 等动作不被这套双人修正覆盖；“复位”仍返回当前单人片段起点，不是切换到标准站姿。

`preview/pair-feet-handshake-0..4.png` 和 `pair-feet-hug-0..4.png` 检查中立站姿、接近、保持、退回与收尾。回归同时测脚掌法线/朝向、站定脚底和踝关节漂移、膝盖逐帧位移及加速度、脚间净空、取消落脚和时间轴拖动一致性；不再只凭脚底没穿地判定支撑稳定。测试阈值是原型工程约束，不是人体运动学医学标准。

## 冻结的骨架约定

- 标识 `besktop.humanoid.v1`，版本 1，24 个节点；固定参考骨长。
- 右手系、米、+Y 向上、+Z 为角色前方；角度计算使用弧度。
- glTF/C++ 四元数 xyzw；Blender Python 的四元数构造顺序 wxyz，只在导出边界转换。
- 本地关节旋转表示姿态；只有 root、pelvis 允许平移。普通骨骼不能通过平移/缩放拉长肢体。
- root 表示地面位移和朝向，pelvis 保留相对高度及摆动；场景缩放/摆放在求解后统一施加，不再叠加第二份位移。
- 参考旋转基准来自 CMU 08_01 转换文件的估计 T 姿态；`tools/animation/rig_profile.json` 定义项目角色比例，含头球的参考冠高约 1.75 米，左右肩关节相对胸口为 ±0.20 米、向上 0.015 米。该配置不是医学人体比例标准。
- 当前比例配置为 `besktop.reference-proportions.v4`，拓扑及骨架标识仍为 v1。左右上臂/前臂分别为 0.31/0.26 米，大腿/小腿为 0.441259551/0.428740449 米；髋关节对称，骨盆高度 1.03 米。仅腿段分配参照固定版本 OpenSim 中立位框架，其余仍是工程选择，不声称全身国标比例。来源与推导见 [人体比例依据](ANTHROPOMETRY.md)。必须成套重建骨架、六条动作与 EXE，不能混用旧比例数据。
- 2026-10-18 首轮校准肩颈后，第二轮校准全身。Blender 和运行程序使用相同参数制作胸腔、腹部、骨盆、手掌和脚掌椭球；普通外观隐藏骨盆中心到髋关节的辅助连线，B 键骨架模式仍显示完整层级。

```text
root
└─ pelvis
   ├─ spine_low → spine → chest
   │                       ├─ neck_base → neck → head
   │                       ├─ clavicle_l → upperarm_l → forearm_l → hand_l
   │                       └─ clavicle_r → upperarm_r → forearm_r → hand_r
   ├─ thigh_l → shin_l → foot_l → toe_l
   └─ thigh_r → shin_r → foot_r → toe_r
```

`spine_low`、`neck_base` 和肩带中部分节点在本次来源参考姿态中为零长度旋转辅助节点。保留其语义和旋转链，不绘制零长度胶囊；不为凑关节数伪造骨长。精确父索引、来源映射和偏移保存在生成的 `skeleton.json` 与制作脚本的 `JOINTS`。

## 制作与运行的分工

`CMU BVH → Blender Python 重定向/修整 → glTF 2.0 → gltf2ozz → .ozz + manifest → EXE 内嵌 BAF1 容器`

- `build_assets.py` 按 BVH 通道原顺序解析；排除转换器插入的 T 姿态首帧。120 Hz 来源降采样为 60 Hz。
- 按世界参考旋转重定向到统一骨架，本地骨长固定。不同演员的根平移按左右腿平均长度归一；裁剪和封接后再按实际脚掌最低点做整条片段的一次固定地面高度校正，不逐帧抹去原始骨盆起伏。
- walk 保留原片 `walk_source` 作对照，选取完整步态周期，尾部 100 毫秒封接；idle 尾部 400 毫秒封接。
- 脚底标记由高度和速度阈值提取，人工可修订；运行时在标记窗口内锁定脚掌椭球的实际支撑点，保留脚踝捕获旋转，支点随脚跟/脚尖滚动而换算到踝关节目标。骨盆先作有限高度补偿，再以双骨 IK 求解；同时修正被骨盆补偿压入地面的摆动脚。当前地面仅为 Y=0 平面，不是通用地形或全身物理。
- manifest 提供时长、循环、下一动作、混合时长、来源和接触区间。Player 负责选择、混合、循环根运动和有限转向；普通动作选择没有每动作一份 C++ 算法。
- 双人 `PairSession` 是专项互动原型：共享 5.2 秒时间线、固定站位、交替落脚、手掌表面和朝向约束、取消恢复。握手对齐双方掌面；拥抱从对方可见胸腔椭球计算背部目标，避免把两个腕关节放在同一点。尚无手指抓握、完整身体碰撞或任意互动生成能力。
- Library 当前按单线程采样设计，不可被多渲染线程共享；需要并发时，每个线程独立持有库及采样上下文。
- BAF1 是内部可信资源容器，不替代 `.bpack`，没有签名/联网下载/运行时第三方导入能力。不要向它输入未受信任的任意 ozz 数据。

## 重建和验证

需要 Visual Studio 2022 C++ 工具链、Windows SDK、CMake 3.24+、PowerShell 和 curl。首次准备需要联网及数 GB 项目缓存空间；不会修改系统 PATH、文件关联或代理。

从 Core 根目录执行：

```powershell
./tools/animation/prepare.ps1 -BuildPreview
./tools/animation/verify.ps1 -Sequences
```

准备脚本验证 `dependencies.json` 的 SHA-256，将便携 Blender、ozz 和四个 BVH 下载到 `out/animation-foundation/`；构建 gltf2ozz，重建制作文件、资源，编译两个 EXE 并运行 CTest。已有下载会验证后复用。仅需重建运行数据时加 `-SkipBlend`，但交付新的制作工程应去掉该开关。首次远程下载仍可能因镜像连接失败；校验失败会停止，不会执行不匹配文件。

验证脚本等待隐藏进程完成并核对新生成标记：普通窗口控件测试、48 个合成桌面图标测试、多角度画面、1080p 人群基准。自动验证不读取真实桌面，也不注册全局快捷键。`out/animation-foundation/preview/frames/` 为可选连续帧。

`fullbody-0..3.png` 是脚底修正开启后的全身四视图，`foot-contact-0..1.png` 是两个行走相位的脚掌近景；`G2-0..3.png` 保留未开运行修正的导入结果作对照。测试测量可见脚底的高度和漂移，而不只测踝关节位置；还覆盖对称骨长、放松步态膝盖反折、不可达 IK 的骨长/过伸边界、握手掌面以及双人手臂对可见躯干的采样净空。它们不能替代完整动作观感或解剖关节限制的验收。

视频编码是单独的开发工具步骤：将 ffmpeg 可执行文件路径传给 `make_video.py`；本机使用项目缓存中 imageio-ffmpeg 0.6.0 带的 ffmpeg 7.1，不随实验 EXE 分发。

```powershell
python tools/animation/make_video.py out/animation-foundation/preview --ffmpeg <ffmpeg.exe完整路径>
```

完成以上生成与验证后，执行 `./tools/animation/package_preview.ps1` 可整理本地预览目录、SHA-256 清单及 ZIP。它还需要 `build-animation-baseline-check/` 的旧版回归日志，不负责发布、提交或推送；不要混入个人桌面截图或额外文件。

只验证旧版不依赖新工具链时，使用独立构建目录并设置 `-DBESKTOP_BUILD_ANIMATION_LAB=OFF`。该选项默认关闭，不触发 ozz 下载或要求 Blender 资源。不要使用旧版公开发布脚本误发布实验构建。

## 如何再加一个普通动作

1. 先确认动作原始/转换数据及衍生运行数据的许可，记录来源；不要只看片段名，还要看主体分类与完整样片。本轮曾据此淘汰舞蹈和篮球候选。
2. 对同一 MotionBuilder 2010 BVH 结构，给 `dependencies.json` 增加下载、描述、SHA-256；给 `clip_sources.json` 增加 name/source/description，可配置 limit_seconds、trim_seconds、loop。
3. 名称使用英文数字和下划线，不重复。固定采样率和关节映射仍须满足 v1；其他骨架/格式需要先做制作端映射，不保证零工作量。
4. 执行准备脚本，检查 Blender 多角度与新 Action。manifest、glTF 及 ozz 会增加轨道，实验场下拉框自动发现，不修改 C++ 动作选择算法。
5. 检查根方向、固定骨长、接触标记、头尾姿态以及从 idle/walk 切入切出。循环片段不能只把 loop 改成 true 就认定无缝，必须先修整。

本轮实际扩展了 stop、turn、celebrate，随后又替换 stop/turn 的源动作，沿用同一运行时。庆祝的关键帧制作函数属于素材生产端；新增普通动捕不需要照抄该函数。握手、拥抱这类接触类型仍可能需要新增约束逻辑，不能承诺全部只加文件。
