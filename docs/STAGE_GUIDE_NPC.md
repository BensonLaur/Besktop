# Besktop 舞台引导角色实施说明

本文定义公开 Core 中品牌引导角色“B仔”的产品边界、状态机、鼠标交互、外链安全流程和实施顺序。完整的私有产品母版保留在 Besktop-Plus；Core 只实现公开、通用且不依赖支付或授权的反馈、自愿支持和安全说明入口。

当前状态：**A–D 已实现并进入发布候选回归，人工视觉与正式外链仍待验收**。实现采用独立纯逻辑状态/布局、code-native GDI+ 身体与运行时四肢，没有修改冻结的普通演员动作、Contact、步态或转身数据。

## 目标

Besktop 是一次性全屏桌面演出，不增加托盘、最小化或默认后台驻留。B仔作为舞台中的唯一品牌角色，在核心 Icon Fight 体验已经成立后出现，让用户通过角色本身发现：

- 官方反馈入口。
- 自愿支持入口。
- 项目与安全说明。

B仔必须像桌面舞台中的角色，而不是悬浮客服按钮、系统组件或真实桌面图标。打开外部网页前必须结束演出并销毁置顶窗口，Besktop 随后退出，不留隐藏进程。

## 当前基础

当前 `StageWindow` 使用 `WS_POPUP` 与 `WS_EX_TOPMOST` 创建无边框全屏窗口，并已接入 `WM_MOUSEMOVE`、`WM_MOUSELEAVE`、`WM_LBUTTONUP`、`WM_SETCURSOR` 与 `TrackMouseEvent`。窗口继续处理键盘、全局强制退出、动画计时、绘制和销毁；指向可点击入口时使用系统手形光标，其余舞台保持箭头。

`IconFightScene` 仍负责普通演员生命周期、相遇池、邻近反应和渲染。B仔以独立 `StageGuideNpcState` 存在，只读取工作区和活动 reservation 的值快照；它不是 `IconActor`，也不进入感知、仲裁、相遇池、交锋或邻近反应容器。

## 公开体验

### 角色外形

- 身体使用 code-native GDI+ 绘制的 Besktop 蓝色圆角 `B` 品牌图形，不复用包含预绘四肢的 master PNG。
- 身体边长约为普通图标演员较大边长的 `1.2–1.3` 倍。
- 复用双面薄片与白色两段式四肢，线宽可以略粗，并使用简单圆形或胶囊端点表现手掌与鞋子。
- `B` 字内部留白可以加入轻量眼神：眨眼、看向光标和左右观察。
- 不使用齿轮、盾牌、Windows 标志、安全警告、金币闪烁或持续红点。

现有 `resources/app/besktop-icon-master.png` 只作为品牌参考；它已经包含预绘四肢，不能直接叠加到运行时骨架上。

### 出场

首选在第一场完整相遇完成 Aftermath 并释放 reservation 后等待约 `1.2–2.0` 秒，再让 B仔从远离事件的安全屏幕边缘进入。演员不足或长期没有正式相遇时，在启动后约 `20–30` 秒使用稳定兜底时刻出场。

出场规则不得改变普通演员的随机序列、觉醒计划、相遇请求或 CombatEpisode。

### 巡场

- 只在有效工作区域内移动。
- 避开任务栏、屏幕边缘和全部活动 reservation。
- 不进入 `EncounterArbiter`、`ActiveEncounterPool`、`CombatPair`、`CombatEpisode` 或 `ActorEventReaction`。
- 活动事件靠近时先收起菜单，再选择安全绕行点。
- 没有安全点时原地等待，不瞬移、不穿越交锋中心。

## Hover 菜单

### 唤起规则

1. 光标进入身体周围约 `1.4` 倍的感应区域。
2. 连续停留约 `180–250ms` 后进入 `NoticingPointer`。
3. B仔减速、停止、看向光标并挥手。
4. 头顶菜单在约 `160–220ms` 内展开。
5. 菜单只冻结 B仔，不暂停普通演员、觉醒和相遇。

所有时间使用 delta time，不按帧数计数。光标短暂掠过不能弹出菜单。

### 菜单内容

| 动作 | 用户文案 | 行为 |
| --- | --- | --- |
| `Feedback` | `反馈` | 打开外链确认卡 |
| `Support` | `支持 B仔` | 打开外链确认卡 |
| `About` | `这是啥？` | 打开舞台内安全说明卡 |

菜单入口必须同时显示图形和短文字。身体、菜单气泡和中间移动走廊组成同一个交互区域；光标从身体移向菜单时保持展开。离开整体区域约 `450–600ms` 后收起。

菜单优先显示在头顶；上方空间不足时翻到下方，靠近左右边缘时向屏幕内偏移。所有命中区域都必须使用同一组 DPI-aware 舞台坐标，不能在屏幕坐标与客户区坐标之间混用。

### 光标

- 普通舞台保持箭头光标。
- 指向可点击气泡或确认按钮时使用 `IDC_HAND`。
- 离开窗口或菜单关闭时恢复箭头。
- 鼠标捕获、窗口失焦或异常销毁时必须清空 hover/pressed 状态。

## 舞台内说明

“这是啥？”打开轻量说明卡，不访问网络。至少说明：

- Besktop 是安全的桌面娱乐演出。
- 不移动、删除或改写真实桌面文件。
- 不自启动、不后台驻留、不提权。
- `P` 切换自动互动，`Esc` 退出。
- 项目名称和公开仓库身份。

说明卡不能模仿 Windows 对话框、安全中心或错误提示。点击卡片外部、关闭按钮或按 `Esc` 都应有清楚结果；`Esc` 继续沿用现有“退出整个 Besktop”语义，不改成只关闭卡片。

## 外链与退出流程

### 原则

置顶舞台存在时直接打开浏览器，浏览器可能位于舞台后面；隐藏舞台继续运行又会形成不透明的后台状态。因此外链统一采用“确认—结束演出—打开网页—进程退出”。

### 顺序

1. 用户点击“反馈”或“支持 B仔”。
2. 场景显示：`将结束本次演出并打开官方网页。`
3. 用户选择 `打开网页` 或 `继续观看`。
4. 确认后播放约 `200–300ms` 的收场动作。
5. 停止计时器，销毁全屏置顶窗口，释放快照和渲染资源。
6. 确认舞台窗口已经销毁后，通过 `ShellExecuteW` 打开系统默认浏览器。
7. Besktop 退出，不创建托盘、不隐藏驻留。

外链请求应以枚举动作在场景与窗口层之间传递，场景层不直接调用 Shell。窗口或应用层只把动作映射到经过批准的固定 HTTPS URL；不得接受桌面文件、Pack、命令行或远程内容提供的任意 URL。

反馈和支持 URL 未得到用户确认时：

- 不写占位链接。
- 普通 Release 不显示无效入口。
- 纯逻辑和窗口测试使用注入的 mock URL/动作处理器。
- 诊断预览可以检查菜单布局，但不能意外打开网页。

## 状态机

```text
Dormant
  等待首场相遇结束或兜底时间。

Entering
  从安全屏幕边缘进入。

Roaming
  在 reservation 外巡场。

NoticingPointer
  光标稳定靠近，减速并看向光标。

PresentingMenu
  菜单展开，等待 hover 或点击。

ShowingAbout
  舞台内说明卡打开。

ConfirmingExternalAction
  等待打开网页或继续观看。

LeavingForExternalAction
  收场并提交外链退出请求。
```

`Esc`、`Ctrl+Shift+B`、窗口关闭和异常销毁从任何状态进入现有安全退出路径。链接未配置、布局失败、指针离开或活动 reservation 靠近时都必须有确定性退化路径。

## 建议代码边界

优先新增独立纯逻辑模块，避免继续扩大 `icon_fight_scene.cpp`：

```text
src/besktop/animation/stage_guide_npc.h/.cpp
  状态、tuning、时间推进、出场、巡场、hover、菜单与外链动作请求

src/besktop/animation/stage_guide_layout.h/.cpp
  身体、气泡、说明卡和确认卡的 DPI-aware 布局与命中区域

tests/stage_guide_npc_tests.cpp
  状态机、时间边界、hover 宽限、reservation 避让和动作单次消费

tests/stage_guide_layout_tests.cpp
  屏幕四边、DPI、菜单翻转、走廊和命中测试
```

集成职责：

- `IconFightScene`：拥有 B仔状态，提供当前活动 reservation 快照，更新和绘制角色/菜单，并暴露指针输入和待消费动作。
- `StageWindow`：处理 `WM_MOUSEMOVE`、`WM_MOUSELEAVE`、`WM_LBUTTONUP`、`WM_SETCURSOR` 与 `TrackMouseEvent`，把客户区坐标传给场景。
- 应用/窗口退出层：消费经过确认的外链动作，在舞台销毁后调用固定白名单 URL。
- 渲染层：使用 code-native GDI+ 身体、光标视线/挥手和独立运行时白色四肢；不复用包含预绘四肢的 master PNG。

上述名称是推荐边界，不是插件公开 API。实现时可以根据现有类型组织微调，但不得把鼠标、Shell 或 URL 依赖塞进纯逻辑测试模块。

## 诊断预览

已增加受既有 `BESKTOP_ENABLE_DIAGNOSTICS=1` 保护的只读预览：

```text
BESKTOP_STAGE_GUIDE_PREVIEW=1
```

预览让 B仔立即出现在安全区域，便于检查 hover、菜单边缘布局、说明卡和确认卡。反馈/支持入口在该模式下只产生 mock 动作：舞台会按正式关闭顺序退出，但不会打开浏览器。普通 Release 未开启 diagnostics 时忽略该变量，也不能获得测试 URL。

## 分阶段实施

### A. 纯逻辑状态与布局（已完成）

- 建立状态机、tuning、出场触发、hover 计时、宽限关闭和动作单次消费。
- 建立工作区域、屏幕四边、气泡走廊和确认卡布局。
- 使用 mock reservation 与 mock 外链动作完成纯逻辑测试。

验收：不创建窗口也能覆盖所有状态转换、边缘布局和异常退化。

### B. 品牌身体与巡场（已完成，视觉待人工验收）

- 使用不含预绘四肢的 code-native 蓝色 B 身体。
- 使用独立的运行时白色两段式四肢、轻量步态与挥手，不复用或改写普通演员的冻结姿态数据。
- 首场相遇后出场，长期无相遇时兜底出场。
- 避开全部活动 reservation，不改变普通演员随机序列。

验收：B仔明显特别但不抢开场，不参加任何交锋或旁观反应。

### C. 鼠标、菜单与说明卡（已完成，视觉待人工验收）

- 接入 Win32 指针消息、`TrackMouseEvent`、手形光标和点击命中。
- 绘制三个菜单气泡、说明卡和确认卡。
- 保证身体到菜单的交互走廊不闪退。

验收：短暂掠过不弹出；四边和不同 DPI 下均可点击且不越界。

### D. 外链退出闭环（代码完成，正式 URL 待配置）

- 使用枚举动作与注入处理器完成测试。
- 只允许源码中明确批准的固定 HTTPS URL；当前两个地址均为空，普通 Release 隐藏相应入口。
- 外链前销毁舞台，浏览器出现后 Besktop 无残留进程。

验收：未经点击与确认不联网；链接缺失不显示无效入口；`Esc` 与强制退出不回归。

### E. 发布候选回归

- x64 Debug、x64 Release、Win32 Release 全量构建和注册测试。
- Pack CLI、普通 Release diagnostics 隔离和双架构退出短测。
- 5 分钟资源稳定性，以及鼠标反复进出、菜单长开、边缘布局压力测试。
- 人工检查 B仔出场、视线、挥手、菜单可读性、战斗避让和浏览器切换。
- 更新 README、技术计划、发布说明和发布清单，重新生成候选哈希。

## 自动测试重点

- 首场相遇触发只消费一次；无相遇兜底可重复复现。
- hover dwell 前不展开，达到阈值后只展开一次。
- 身体、菜单和走廊之间移动不关闭；离开宽限后关闭。
- 鼠标离窗、失焦、取消点击和窗口销毁清空状态。
- 菜单在上、下、左、右边缘及 100%/125%/150% DPI 下保持工作区内。
- B仔的目标和路径避开全部活动 reservation。
- B仔不会出现在普通演员、意图、仲裁、相遇池或事件反应输入中。
- About 不产生外链；Feedback/Support 需点击和确认后各产生一次动作。
- URL 缺失时普通 Release 不显示对应入口。
- 诊断预览不能绕过 Release 总开关，也不能启动浏览器。
- 外链动作、关闭窗口和 Shell 调用顺序可通过注入处理器测试。

## 人工验收

- B仔尺寸、蓝色身体、白色四肢和眼神一眼可识别，但不压过真实桌面图标。
- 第一场相遇余波结束后再出场，不打断核心叙事。
- hover 反应像角色注意到用户，不像客服浮窗自动弹出。
- 三个入口文案清楚，打赏表达自愿且克制。
- 战斗靠近时菜单收起和避让自然，不瞬移。
- “这是啥？”安全说明可信，不像系统警告。
- 外链确认后真实桌面恢复，再出现浏览器；没有黑屏、被舞台遮挡或残留进程。
- 普通用户始终可以不理会 B仔，只观看演出并按 `Esc` 退出。

## 明确不做

- 托盘、最小化、后台恢复或自动启动。
- 设置窗口、账号、聊天机器人、语音或远程内容。
- 多个品牌 NPC、皮肤商店或角色养成。
- 让 B仔攻击、受击、倒地或改变 Combat 结果。
- 自动上传桌面内容、截图、日志、路径或设备信息。
- 从 Pack、命令行或网络下发任意 URL。
- 未经用户确认的打赏链接、埋点或商业追踪。

完成该功能后，v0.1.0 再次冻结；后续功能应依据 pre-release 的真实反馈决定。
