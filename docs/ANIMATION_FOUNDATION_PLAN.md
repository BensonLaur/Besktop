# 三维角色与动作基础验证计划

- 决策日期：2026-09-27。
- 状态：方向已确认，文档规划；未开始本计划的新架构实现。
- 当前阶段：三维角色与动作验证。
- 适用范围：公开 Core 的统一骨架、动作生产与导入、运行时、验证工具及后续场景适配。

## 1. 目标与优先级

先让一个独立三维火柴人具备自然、可信、可持续扩展的动作，再把桌面图标作为外观与场景接入。新阶段不以图标薄片、图标尺度或全屏桌面演出作为骨架的前置条件。

首个可运行交付目标：一个可以自由观察、暂停和慢放的三维火柴人，正确播放外部动作，且增加普通单人动作不需要修改动作算法。

骨架本身不足以解决扩展问题。本计划同时建立“统一骨架 + 可视化制作与适配 + 可复现导入 + 播放与混合 + 接触修正”的最小闭环。

这不是重新创建整个 Besktop，也不是自研通用游戏引擎。现有 Icon Fight 路径作为历史产品基线保留；其实现事实和验证记录继续有效，但旧的图标优先顺序不再决定新阶段。

本计划仅确认方向和验收标准，不构成自动实现、安装依赖、采购、发布、提交或推送授权。

## 2. 重建与保留范围

| 部分 | 处理方式 |
| --- | --- |
| 桌面快照、窗口生命周期、安全退出、构建与已有发布流程 | 保留；实验入口不加载桌面快照、不进入全屏桌面舞台 |
| 测试、诊断和 Pack MVP | 保留；新能力不要求先修改现有内容包协议 |
| 相遇、占用、安全仲裁和双人共享时间线 | 后续评估适配，暂不拖入首个实验；不承诺原代码无需修改 |
| 两段式 IK 数学和相关测试 | 评估复用，剥离图标尺度、轴向和特殊弯曲提示 |
| 图标挂接、薄片投影与旧 ActionSample 通道 | 留在旧路径中，不作为新骨架协议 |
| 标准骨架、导入、混合、根运动协调、接触约束、三维角色渲染 | 独立建立或重构 |

优先在现有 Core 仓库内增加独立可执行目标，暂名 `AnimationLab`。名称、目录与 CMake target 在实现任务中确定，不把本文中的名称当作已经存在的命令或产物。

已有工作区修改必须保留。实现前重新检查状态，使用合适的独立开发工作区隔离；不删除旧模块，不重置当前分支，不自动迁移或提交他人的未完成改动。

## 3. 统一人形骨架约定

“标准”指项目内明确、稳定、可映射的约定，不存在本计划保证直接兼容的唯一通用人体骨架。

第一版拟采用约 22–26 个关节，不包含手指和面部：根节点、骨盆、脊柱、胸部、颈部、头部，左右肩带、上臂、前臂、手、大腿、小腿、脚和脚趾支点。具体关节表在 G1 依据样片冻结，数量不是验收指标。

在第一条素材导入前明确并记录：

1. **空间约定**：统一长度单位（建议米）、坐标系手性、向上轴、角色前向及角度单位；导入边界统一转换，不在各动作里单独修补。
2. **结构约定**：关节语义、父子层级、本地坐标轴、固定骨长、参考姿态与来源骨架映射。
3. **根与骨盆**：根节点描述整体运动，骨盆描述身体相对根节点的运动；场景移动和 RootMotion 只能按明确策略应用一次。
4. **姿态表达**：关节本地旋转轨道与连续插值，明确平移轨道适用范围；不得通过随意拉长四肢伪造动作。
5. **数据兼容**：骨架标识与版本、动作时长、循环策略、根位移、接触与事件标记；不兼容输入须明确报错。
6. **职责分离**：动作不引用图标纹理、桌面像素或 `planeSide`；角色比例、可见外观、场景和动画数据独立。

冻结一套首轮参考姿态与比例后先把单条导入链跑通。第一版不承诺运行时自动适配任意骨架、任意比例或全部文件格式。

## 4. 最小三维表现

火柴人使用球形头部、胶囊体四肢、简化胸部和骨盆。简单几何跟随骨骼即可，不要求先做完整蒙皮。

实验环境提供普通窗口、地面网格、简单光照、透视摄像机和正确的深度遮挡。骨架是真实三维空间中的层级结构，不是靠二维线段缩放伪装深度。

第一阶段不包含复杂材质、衣服、肌肉、面部、完整全身物理仿真或电影级效果。摄像机与深度遮挡首先用于发现动作问题，而不是增加装饰。

## 5. 技术候选与数据生产流程

维持 C++20、Win32、CMake / Visual Studio 的 Windows 原生方向；小体积、启动快、低运行时依赖仍是评估目标。

| 环节 | 首选验证方向 | 边界 |
| --- | --- | --- |
| 骨架、样片、重定向和动作修整 | Blender | 制作端工具，不随产品分发；重定向仍需实际适配 |
| 动作加载、采样和混合 | ozz-animation | 候选依赖，尚未集成；不代替整个角色控制或互动系统 |
| 独立实验程序三维渲染 | Direct3D 11 | 新入口验证，不要求立即重写旧 GDI+ 桌面渲染链 |
| 动作选择、过渡、根运动、脚底与双人接触 | Core 自身逻辑与必要 IK | 保持边界清楚，避免按每个普通动作写特例 |

首轮只选一条经过验证的资源路线：将 FBX / BVH 等来源动作在制作工具中适配到统一骨架，导出选定的 glTF 或 FBX 中间格式，再离线转换为运行时数据。若采用 ozz，可验证其 `gltf2ozz` 或 `fbx2ozz` 工具，不要求两条路径同时完成。

骨架映射与动作重定向不等同于文件格式转换。应保留原始来源、制作文件、导出参数、工具版本和可复现转换步骤，能追溯旋转轴、单位和根位移错误。

运行时数据之外，按需要保存接触标记、循环信息和事件元数据，不假定通用交换格式自动提供所有语义。制作端的依赖无需全部进入最终 EXE。

动画库与导入工具以原型验证结果决定是否采纳，不能把本计划写成已完成的能力承诺。参考资料：

- [ozz-animation 项目与运行时依赖说明](https://github.com/guillaumeblanc/ozz-animation)。
- [ozz-animation 离线转换工具](https://guillaumeblanc.github.io/ozz-animation/documentation/toolset/)。
- [ozz-animation IK 说明](https://guillaumeblanc.github.io/ozz-animation/documentation/ik/)。

若原生路线的开发成本与效果不匹配，应记录测量和样片，再讨论是否放宽体积、发布或运行时约束；未重新决策前，不自动切换大型游戏引擎。

## 6. 分阶段检查点

### G1：制作端骨架与样片

交付物：火柴人制作文件、骨架约定、来源明确的质量合格外部动作及多角度样片。

通过标准：

- 在正面、侧面、背面和自由视角下确认比例与关节活动合理。
- 动作具有可辨认的重心、预备、惯性、收势和表演意图。
- 至少一段代表动作在制作工具中得到人工观感认可，再投入运行时建设。
- 记录素材来源、许可、骨架映射和导出步骤；不把仅可成品使用的资产擅自提交为公开原始数据。

### G2：独立实验程序

交付物：普通窗口中的三维火柴人，加载与 G1 相同的骨架和动作。

通过标准：

- 与制作工具中的相同时间点、相同视角结果一致，没有错误镜像、轴向、缩放、翻转或根位移重复。
- 支持暂停、逐帧、慢放、时间拖动、摄像机旋转与缩放。
- 能显示骨架、根节点轨迹、接触点（有标记时）与帧耗时，能切换动作并比较原始与修正结果。
- 不读取真实桌面图标、不全屏覆盖桌面、不依赖旧产品启动流程；正常关闭与明确退出操作可靠。

### G3：连续运动与动作扩展

交付物：站立、走路、停止、转身、庆祝及相互切换，含必要的根运动与脚底接触修正。

通过标准：

- 动作切换无明显跳姿态，步幅与实际位移匹配，支撑脚不明显滑动。
- 停止、转向和重新行走不会重复位移、瞬移或继续错误播放步态。
- 第四、第五个普通单人动作主要通过资源导入、适配与配置完成，不新增对应动作专用的 C++ 分支。
- 记录实际新增动作的操作步骤、修整工作和遇到的限制，而不只展示已有样片。

### G4：双人接触风险验证

交付物：先击掌或握手，再完成拥抱风险样片；在 G3 后尽早验证，不以扩充大量单人动作作为前置条件。

通过标准：

- 双方有一致的时间基准、相对站位和朝向，接近、接触、保持、释放、收尾可控。
- 接触点与双方身体比例对应，手部不会明显抱空或穿过对方；不依赖两段独立动画偶然对齐。
- 明确测试的身高、比例、距离范围，不承诺任意体型自动适配。
- 异常取消或正常收尾后释放双方控制，恢复到合理姿态。

新的接触类型可能需要专门约束或逻辑，这不等于普通单人动作数据化失败。

### G5：场景与图标适配

交付物：将已验证动画核心接回 Besktop 舞台，再验证图标外观。

通过标准：

- 火柴人与图标角色共用动画核心，图标作为外观挂接，不重写另一套动作播放器。
- 验证肩胯挂点、身体比例、图标可辨认性与实际桌面尺寸下的可读性。
- 原有安全退出、真实桌面不变性和 Pack MVP 不被破坏。
- 在声明的目标机器和演员数量下记录性能及资源回归；旧 GDI+ 基线不能直接当作新运行时性能证明。

`AnimationLab` 是开发工具，不改变最终面向用户一个 `Besktop.exe` 的方向，也不意味着所有图标都无需适配。

## 7. 验证记录与故障定位

每个检查点保留：输入素材与版本、转换参数、测试机器与角色数量、自动检查结果、多角度样片、人工观感结论、未解决问题。文件大小、启动和帧耗时应实际测量，不预先承诺尚未测试的上限。

自动检查至少覆盖骨架层级有效性、轨道兼容、采样边界与循环、固定骨长、根位移单次应用，以及后续加入的事件单次消费和接触约束。观感验收另行记录，编译和测试通过不能代替它。

定位顺序：

1. 制作工具中的标准角色也不自然：检查来源动作和修整。
2. 制作端自然、程序结果不同：检查格式转换、轴向、单位和运行时。
3. 火柴人自然、图标不自然：检查比例和外观挂接。
4. 单人自然、双人不自然：检查相对站位、同步、接触与穿模处理。

“接近真人”在本阶段具体指节奏、重心、惯性、情绪和接触可信，不用无边界的“无限接近”作为验收指标。

## 8. 当前不做与保留边界

- 不从零创建另一个完整产品，不删除已有桌面与旧动画实现。
- 不先做通用编辑器、脚本语言、完整物理角色或任意动作自动生成系统。
- 不把购买动捕硬件作为启动条件；优先使用许可明确的素材或现有设备，确认采集成为瓶颈后另行评估。
- 不承诺动捕能免除修整、重定向或双人接触工作。
- 不接入支付、授权生产服务或私有玩法素材；通用骨架、播放和接触能力属于 Core。
- 不自动取消或发布现有 v0.1.0 候选；旧版维护与发布须有单独明确任务。
- 不自启、不驻留、不提权、不修改真实桌面；保留可控退出。
- 开始实现前重新检查 `AGENTS.md`、工作区和任务范围；本轮文档不自动启动实现。
