# Besktop 路线图草案

路线图按“先文档，后原型，再产品化”的顺序推进。

## 阶段 0：文档和边界

目标：把项目方向写清楚，避免边做边改大方向。

- 明确产品定位：桌面娱乐小工具，首个玩法 Icon Fight。
- 明确开源与商业关系：Core 开源，Plus 私有商业扩展。
- 明确发布形态：用户下载一个 `Besktop.exe`，Plus 是内部扩展层。
- 明确文档语言：项目文档默认使用中文。
- 明确提交规范：使用约定式提交，摘要使用中文。
- 明确技能系统：通过 `AGENTS.md` 和 `.agent-skills/` 记录长期流程。

## 阶段 1：感染演出视觉 MVP（已完成）

目标：证明“桌面舞台 + 全量图标演员 + 基础动作”能在 Windows 上自然呈现。当前已完成分波觉醒、邻近扩散、自由漫游、步态 IK、连续 3D 转身和第一轮动作系统。

- 将 GUI `besktop` 从 MessageBox 壳改为 Win32 全屏应用壳。
- 创建覆盖主显示器和任务栏的桌面舞台窗口。
- 支持 `Esc` 退出，预留强制退出热键。
- 建立 `DesktopSnapshot` 数据模型。
- 重绘壁纸、图标、图标文字和任务栏静态视觉。
- 让捕获到的全部有效桌面图标成为演员并长出白色手脚。
- 实现 Locomotion MVP：错峰觉醒、随机目标漫游、停留、转身、脚落地和手脚反相摆动。
- 在觉醒漫游体验稳定后，按 [FIGHT_ACTION_CATALOG.md](FIGHT_ACTION_CATALOG.md) 和 [FIGHT_ACTION_IMPLEMENTATION.md](FIGHT_ACTION_IMPLEMENTATION.md) 分阶段实现第一轮攻击、防守、受击和打空反馈。
- 实现图标本体的双面薄片翻转：左转、右转仍显示正常图标，侧面对屏幕时接近一条窄线。
- 实现局部 3D 两段式手脚骨架，让手脚像长在图标薄片外侧，而不是贴在同一个平面上。

## 阶段 2：真实桌面舞台采集增强

目标：从 demo actor 过渡到稳定读取和复刻真实桌面舞台。

- 通过 `IDesktopWallpaper` 获取壁纸路径和显示方式。
- 当前 MVP 通过桌面 `SysListView32` 只读采样读取图标位置和名称。
- 后续替换或补强为 Shell View / `IFolderView` 与 Shell 图像接口。
- 由 Besktop 绘制图标文字，支持抖动、错位、淡出。
- 截取任务栏静态视觉。
- 处理高 DPI。
- 初步处理多显示器，至少保证主显示器稳定。
- 处理 Explorer 重启、桌面刷新、图标变化。
- 建立壁纸、图标、文字、任务栏采集失败时的降级路径。

## 阶段 3：免费体验打磨（v0.1.0 已收口）

目标：让免费版足够好玩，愿意被传播。v0.1.0 默认体验已冻结为分波觉醒、自由漫游、局部并行相遇、完整交锋和克制的邻近反应；当前转入发布候选人工验收。

- 已完成第一轮基础动作组合，以及轻量 `ActionClip + IK + Contact` 运行时。
- 已完成个体倾向、局部感知、双向意图、安全仲裁、多场相遇池和完整交锋段。
- 已完成邻近演员的注意、观察与避让，以及 `P` 键自动互动切换。
- v0.1.0 不增加设置窗口、托盘、血量、胜负或多人围攻。
- 完成视觉、桌面安全、Windows/DPI/任务栏、SmartScreen 和干净机器人工验收。
- 用户决定官方支持/打赏入口后再写入真实 URL，不使用占位链接。

## 阶段 4：Plus 商业闭环

目标：在不影响免费传播的前提下，加入付费高级玩法。

- 定义内部玩法包格式。
- 支持签名玩法包或签名内置资源。
- 接入兑换码激活。
- 支持本地授权验证。
- 与 Besktop-Plus 的支付授权服务打通。
- 验证 Besktop-Plus 是否能同步 Core 并打包出最终单 exe。
